# Algorithm Evaluator (Detectors Validator)

Веб-застосунок для оцінки та візуалізації роботи алгоритмів комп'ютерного зору (сегментація та детекція об'єктів). Дозволяє завантажувати фото і відео, застосовувати моделі (зокрема YOLO) та порівнювати результати з еталонною розміткою (Ground Truth).

## Основний функціонал

*   **Підтримка фото та відео:** Аналіз як окремих зображень, так і відеопотоків.
*   **Інтерактивний UI:** Завантаження файлів перетягуванням (Drag & Drop).
*   **Автоматичний аналіз:** Миттєвий розрахунок метрик при виборі файлу.
*   **Різні режими перегляду:** Оригінал, результат моделі, або пліч-о-пліч (Side-by-side).
*   **Автоматичний пошук розмітки:** Вкажіть шлях до `dataset.yaml`, і система самостійно знайде відповідні `.txt` файли розмітки у форматі YOLO.

## Як рахуються метрики та оцінки (Core Logic)

Програма робить акцент на математично коректній оцінці алгоритмів. Нижче наведено деталі розрахунку основних показників.

### Швидкодія (Performance)

*   **Час інференсу (ms):** Витягується безпосередньо з рушія моделі (наприклад, з атрибуту `speed` для YOLO). Це чистий час роботи нейромережі на один кадр, без врахування часу на відмальовування інтерфейсу чи передачу по мережі. Бажане значення для real-time систем: **< 50ms**.
*   **FPS:** Розраховується як `1 / (час_обробки_кадру_на_сервері)`. Відображає реальну пропускну здатність системи, включно з декодуванням відео та інференсом.

### Метрики детекції та сегментації

Основою для оцінки є жадібний алгоритм співставлення (Greedy Matching):

1.  Для кожного передбаченого об'єкта та об'єкта з еталонної розмітки (Ground Truth, GT) розраховується **IoU (Intersection over Union)**. Для сегментації порівнюються попіксельні маски, для детекції — площі обмежувальних рамок (боксів).
2.  Об'єкти вважаються "співставленими" (True Positive, **TP**), якщо їхній IoU перевищує поріг **0.5**.
3.  Якщо передбачення не знайшло відповідного об'єкта в GT — фіксується False Positive (**FP**).
4.  Якщо об'єкт в GT не був знайдений моделлю — фіксується False Negative (**FN**).

На базі отриманих значень TP, FP та FN розраховуються класичні метрики якості:
*   **Precision (Точність):** `TP / (TP + FP)` — відсоток правильно знайдених об'єктів серед усіх передбачень моделі.
*   **Recall (Повнота):** `TP / (TP + FN)` — частка знайдених об'єктів відносно всієї їхньої кількості у Ground Truth.
*   **F1-Score:** `2 * (Precision * Recall) / (Precision + Recall)` — гармонійне середнє між точністю та повнотою (загальна метрика якості).

### Темпоральні метрики для відео

Для аналізу відеопотоку застосовується ковзне вікно (Rolling Window) на останні 50 кадрів. Це дозволяє оцінювати стабільність моделі в динаміці, а не лише на поодиноких кадрах:

*   **Temporal Jitter (Тремтіння):** Вимірюється Евклідова відстань (у пікселях) між центрами масок або боксів одного й того ж об'єкта на сусідніх кадрах. Цей показник демонструє, наскільки сильно "стрибає" передбачення, навіть якщо об'єкт залишається нерухомим. Менше значення — краще (ідеально < 5px).
*   **Flicker Rate (Мерехтіння):** Аналізується стабільність детекції об'єкта на послідовності кадрів (є детекція або її немає). Розраховується відсоток кадрів, де статус детекції змінюється. Це допомагає виявляти моделі, які "гублять" об'єкт на долю секунди. Бажане значення: **< 5%**.

## Технологічний стек

*   **Backend:** Python, FastAPI, Uvicorn, WebSockets
*   **Computer Vision:** OpenCV (`cv2`), Ultralytics (YOLO), NumPy
*   **Frontend:** HTML5, Vanilla JavaScript, CSS

## Структура проекту

*   `main.py` / `sample_and_run.py` — скрипти для базового тестування та запуску.
*   `evaluator.py` — ядро оцінки: завантаження розмітки, порівняння передбачень та розрахунок метрик.
*   `metrics.py` — математичні функції для обчислення IoU, Precision, Recall, F1, Jitter та Flicker.
*   `models/` — абстракції та адаптери моделей.
    *   `base_model.py`, `base_video_model.py` — базові класи.
    *   `yolo_model.py` — реалізація адаптера для моделей архітектури YOLO.
*   `web_app/` — серверна частина та фронтенд.
    *   `server.py` — FastAPI сервер, API ендпоінти (`/api/process`, `/api/pick_file`) та WebSocket з'єднання (`/ws/video`).
    *   `static/` — веб-інтерфейс (файли `index.html`, `app.js`, `style.css`).

## Встановлення та запуск

1.  **Встановіть залежності:**
    ```bash
    pip install -r requirements.txt
    ```
2.  **Запустіть веб-сервер:**
    ```bash
    python -m uvicorn web_app.server:app --host 127.0.0.1 --port 8000
    ```
3.  **Відкрийте браузер** за адресою [http://127.0.0.1:8000](http://127.0.0.1:8000)

## Використання

1.  У лівій панелі інтерфейсу знайдіть поле **"Розмітка GT (dataset.yaml)"**.
2.  Вкажіть шлях до конфігураційного файлу вашого датасету. За замовчуванням система пропонує шлях до сусідньої теки.
3.  Завантажте фото або відео, яке міститься у цьому датасеті.
4.  Система автоматично знайде відповідні `.txt` файли розмітки та відобразить панель **"Метрики зображення"** або **"Live Metrics"** з розрахованими показниками.
